<aside>
🛰️

How Shield behaves at runtime: topology, contracts, queues, caching, retries, hot, warm and cold paths, active-active cells, realtime media, observability and degradation. Two rules run through all of it. **No model output and no dependency failure can ever produce a good result.** Missing evidence becomes `unknown`, and `unknown` never lowers risk. **Every write is idempotent**, so anything can be retried, replayed or run twice safely.

</aside>

## 1. Topology

```
                      Global control plane  (no personal data)
        tenants · hashed API credentials · policy and model registries (signed)
             feature flags · system mode · hashed scam-intel exchange
                                      │
 Public users, banks, telcos ──► Edge: WAF · DDoS · bot rules · region steering
                                      │
        ┌───────────────────┬─────────┴───────────┬─────────────────────┐
        ▼                   ▼                     ▼                     ▼
  Cell AE (UAE)      Cell KE (Kenya)      Cell UG (Uganda)     Cell TZ (Tanzania)
     Each cell runs the same stack, in-country, across two zones:

     Gateway API ........ Bun · Hono · Zod · OpenAPI 3.1
     Channel adapters ... WhatsApp Cloud API · USSD and SMS aggregators · APNs / FCM
     Media gateway ...... Twilio <Start><Stream> fork or local SIP trunk → WebSocket
                          SIP leg → ElevenLabs Agents (Guardian)
     Decision engine .... pure TypeScript, no I/O, versioned signed policies
     Detect service ..... D1 ElevenLabs AI Speech Classifier · D2 vendor · D3 in-house (GPU, ONNX)
     Telco adapters ..... CAMARA aggregator · MTN Uganda direct · others per market
     Postgres 16 ........ primary + synchronous standby + witness · pg-boss · outbox · audit chain
     Valkey ............. cache · rate limits · locks · session checkpoints
     Object store ....... WORM evidence (object lock) · tmpfs scratch for audio
```

- **Cells are independent.** Each country's personal data lives and is processed in its own cell. A cell can fail without affecting the others.
- **The control plane holds no personal data.** It distributes signed policies, model versions, flags and the system mode.
- **The scam-intel exchange** shares only keyed HMAC hashes of numbers and aggregate counts between cells, never raw numbers, audio or names.

## 2. Hot, warm and cold paths

| Path | Examples | Budget | How it runs |
| --- | --- | --- | --- |
| Hot: someone is on a call right now | Guardian challenge scoring | Result 1.5 s or less after the caller stops speaking | In-process engine, hedged detectors, no queue |
| Hot: bank is about to act | `POST /v1/otp-guard` | p95 150 ms or less with a warm cache, p99 800 ms or less with a live telco call | Subscription-fed cache, telco call only on miss |
| Hot | `GET /v1/verified-calls/lookup` | p95 100 ms or less | Cache plus primary-key read |
| Hot | `POST /v1/assess` | p95 250 ms or less without audio, 3 s or less with up to 30 s of audio | Engine plus parallel signal fetch |
| Hot: channel | USSD screen · app number check · WhatsApp verdict | 2 s per screen · p95 1.5 s · p95 10 s | Channel adapters, then the same engine |
| Warm: minutes | Tenant webhooks · reputation recompute · scam-wave clustering · telco subscription renewal | p95 60 s · 5 min · every 5 min · before expiry | pg-boss queues |
| Cold: batch | Policy backtests · eval runs · evidence packs · archive · retention purge | Backtest of 30 days of traffic in 20 min or less · daily purge | Low-priority queues, separate pools |

## 3. Data temperature and retention

| Tier | Store | Contents | Retention |
| --- | --- | --- | --- |
| Hot | Valkey (per cell) | SIM and forwarding status cache, rate limits, idempotency keys, Guardian checkpoints | Seconds to 24 h |
| Warm | Postgres (per cell) | Decisions, signals, cases, holds, verified calls, reports, reputation, audit chain | 13 months online by default, set per tenant contract |
| Cold | Object store with object lock (WORM) | Evidence packs, sealed audit segments, eval manifests | Bank evidence 7 years by default, set per contract and law |
| Never stored | Nowhere | Raw public audio after scoring, voiceprints, safe words, OTP values, PINs | Not applicable |

**Public audio** is processed in memory or on tmpfs, under a per-clip data key, and deleted within 60 s of scoring by destroying the key (crypto-shred). Only derived features and an **acoustic fingerprint of the recording** are kept, for 30 days, to deduplicate forwards and cluster scam waves. A fingerprint identifies a clip, not a speaker. It is not a voiceprint.

**Business tenants** can opt in to keep call audio as evidence under their own key (BYOK), with retention set by contract.

## 4. Request lifecycle

Middleware runs in this order on every request:

1. **Edge:** TLS 1.3, WAF, bot rules, region steering by tenant or phone prefix.
2. **Correlation:** `requestId` and W3C `traceparent`.
3. **Region guard:** if the tenant's data region is not this cell, return `SH-REGION-421` (Misdirected Request) with the correct base URL. Personal data is never proxied between cells.
4. **Authentication:** mTLS plus OAuth 2.0 (business), device-bound session (app), signature checks (channel and vendor webhooks).
5. **Authorisation:** scopes such as `assess:write` and `holds:release`. Tenant isolation through Postgres row-level security.
6. **Rate limits:** token buckets in Valkey per credential, tenant and subject number.
7. **Idempotency:** look up `Idempotency-Key`. Replay the stored response if found.
8. **Validation:** strict Zod schemas. Unknown fields on writes are rejected.
9. **Consent and legal guard:** for example, the Guardian only scores audio after the disclosure has played. Otherwise `SH-CONSENT-451`.
10. **Handler:** fetch signals in parallel → pure engine → write the decision, outbox event and audit entry **in one transaction**.
11. **Response headers:** `Shield-Decision-Id`, `Shield-Policy-Version`, `Shield-Mode`.

## 6. Core contracts

### 6.1 `POST /v1/assess`

One risk decision for a moment of risk: adding a payee, a large transfer, a password reset, a call-centre verification.

```json
{
  "subject": { "msisdn": "+256772123456" },
  "context": {
    "event": "payee_add",
    "channel": "call_centre",
    "amount": { "amountMinor": 2500000, "currency": "UGX" },
    "externalRef": "txn_88412"
  },
  "checks": ["sim_swap", "call_forwarding", "reputation", "voice"],
  "audio": { "uploadId": "upl_01JB7X…" },
  "simSwapMaxAgeHours": 72
}
```

```json
{
  "decisionId": "dec_01JB8Q2K7Z…",
  "decision": "hold",
  "riskBand": "high",
  "reasons": [
    { "code": "SIM_SWAP_RECENT", "detail": { "hoursAgo": 2 } },
    { "code": "VOICE_SYNTHETIC_LIKELY", "detail": { "generalDetectorsAgreeing": 2 } }
  ],
  "signals": {
    "simSwap": { "status": "swapped", "source": "camara", "checkedAt": "2025-10-21T09:14:03Z" },
    "callForwarding": { "status": "unknown", "reason": "SIGNAL_UNAVAILABLE", "error": "SH-TELCO-504" },
    "voice": { "status": "synthetic_likely", "detectorsRun": 3 },
    "reputation": { "status": "reported", "independentReporters14d": 9 }
  },
  "recommendedActions": ["hold_transfer", "step_up_out_of_band"],
  "policyVersion": "ug-banking-2025.10.3",
  "mode": "NORMAL",
  "expiresAt": "2025-10-21T09:24:03Z"
}
```

- `decision` is one of `allow`, `step_up`, `hold`, `block`. `riskBand` is one of `low`, `medium`, `high`, `unknown`.
- **Dependency failures inside `assess` are not errors.** They come back as a signal with `status: unknown` and reason `SIGNAL_UNAVAILABLE`. Policies map that to at least `step_up` for high-value events, so the bank always gets a usable answer.
- **Client contract, tested in certification:** on timeout, network error or any 5xx, the bank's integration treats the result as `step_up`. It never defaults to `allow`.

## 9. Rate limits and abuse resistance

| Caller | Default limit |
| --- | --- |
| Business credential | 200 rps, burst 400 (set by contract). 20 per minute per subject number. |
| App user | 30 number checks and 10 voice checks per day |
| WhatsApp user | 20 messages per minute, 30 checks per day |
| USSD | 1 concurrent session per number |
| Anonymous web | 5 checks per day per device, plus Turnstile |

**Oracle attacks.** A scammer may use Shield to test a cloned voice until it passes. Defences:

- Public results are coarse bands. Scores, thresholds and per-detector results never leave the cell.
- "Detectors unsure" and "detector failed" both show as **Inconclusive**, so failures teach nothing.
- Probe detection: many near-duplicate clips (acoustic-fingerprint similarity), bursts from one account or device, or a voice similar across many "different" callers. Probing accounts silently get Inconclusive and are flagged for review.

**Reputation poisoning.** A number is publicly labelled "reported" only with **3 or more independent reporters in 14 days** (unlinked, verified devices) or one confirmed bank or telco report. Labels decay without new reports. Every label has an appeal path with a 72-hour review target.

## 11. Queues

pg-boss runs on each cell's Postgres, so a state change and its outbox event commit in the same transaction.

| Queue | Flow | Priority | Retry | Dead-letter | Shed under load |
| --- | --- | --- | --- | --- | --- |
| `whatsapp.ingest` | Hook → router (ack under 1 s) | P1 | 5×, exponential | Yes | No |
| `audio.fetch` | Router → media download | P1 | 3× | Yes | No |
| `audio.detect` | Media → detect service | P1 | Hedged once | Yes | No |

| `reputation.recompute` | Reports → bands | P2 | 3× | Yes | Yes |
| `waves.cluster` | Every 5 min | P2 | Next run | No | Yes |
| `telco.subscription.renew` | Before expiry | P1 | 5× | Yes | No |

## 12. Retries, hedging and timeouts

| Dependency | Timeout | Retries | Notes |
| --- | --- | --- | --- |
| D1 ElevenLabs classifier | 1.2 s | 1 hedged request | Positive evidence only (section 12.2) |
| D2 vendor detector | 1.2 s | 1 hedged request |  |
| D3 in-house detector | 0.8 s | None (local) |  |
| CAMARA SIM Swap / Call Forwarding | 600 ms | 1 with jitter | Cache first |
| MTN Uganda SIM Swap | 800 ms | 1 with jitter | Cache first |
| WhatsApp Cloud API send | 5 s | 6 over 10 min | Respect 429, then SMS fallback |
| SMS aggregator | 5 s | 5, then secondary aggregator |  |
| APNs / FCM | 5 s | 3 |  |
| Tenant webhooks | 10 s | 12 over 24 h | Then dead-letter and alert |
| ElevenLabs post-call (inbound) | Ack in 2 s or less | Sender retries | Processed asynchronously |
| LLM (helper chat, console copilot) | 8 s | 1 fallback model | Never in a decision path |

Backoff is exponential with **full jitter**: `sleep = random(0, min(cap, base × 2^attempt))`. Retries only happen on idempotent operations or with the same idempotency key.

### 12.1 Hedged detector fan-out

```tsx
// Run every enabled detector in parallel inside one budget; hedge slow remote calls once.
export async function scoreAudio(clip: Clip, detectors: Detector[], budgetMs = 1500): Promise<DetectorRun[]> {
  const signal = AbortSignal.timeout(budgetMs);
  return Promise.all(
    detectors.map((d) =>
      hedge(() => d.score(clip, { signal }), { afterMs: d.p95Ms, maxAttempts: d.remote ? 2 : 1 })
        .then((r): DetectorRun => ({ id: d.id, version: d.version, scope: d.scope, ok: true, score: r.score }))
        .catch((e): DetectorRun => ({ id: d.id, version: d.version, scope: d.scope, ok: false, error: classify(e) })),
    ),
  );
}
```

### 12.2 The voice-signal floor

```tsx
// The only place a voice signal is decided. Pure, versioned, property-tested.
// scope "provider" = can only recognise one vendor's audio (e.g. the ElevenLabs classifier).
// scope "general"  = trained to detect synthetic speech from many generators.
export function voiceSignal(runs: DetectorRun[], t: Thresholds): VoiceSignal {
  const ok = runs.filter((r) => r.ok);
  const synthetic = ok.filter((r) => r.score >= t.synthetic[r.id]).length;
  if (synthetic >= 2 || ok.some((r) => r.scope === "provider" && r.score >= t.provider[r.id])) {
    return { status: "synthetic_likely" }; // warnings may fire on partial evidence
  }
  const general = ok.filter((r) => r.scope === "general");
  if (ok.length < runs.length || general.length < 2) {
    return { status: "unknown", reason: "SIGNAL_UNAVAILABLE" }; // never "no signs" on missing evidence
  }
  if (general.every((r) => r.score <= t.genuine[r.id])) return { status: "no_signs" };
  return { status: "uncertain" };
}
```

- A provider-scoped "no" (for example, "not made with ElevenLabs") is **never** counted as evidence of a human voice.
- A `no_signs` voice signal needs **every** detector to answer and **at least two general detectors** to agree.
- Property tests assert that removing any detector run can never move a result towards Clear.

### 12.3 Circuit breakers, bulkheads and budgets

- **Breakers** per dependency per cell: open at 50% failures over 20 calls in 30 s, or at p95 above 2× budget. Probe again after 15 s. While open, the signal returns `unknown` immediately, and the mode controller may switch to DEGRADED_DETECTION or TELCO_DEGRADED.
- **Bulkheads:** separate worker and connection pools for business hot paths, public channels, Guardian media and batch. Postgres pool split: hot 60%, channels 25%, batch 15%. Batch can never starve a live call.
- **Budgets:** agent server-tool handlers 800 ms · Guardian session maximum 6 min · challenge answer window 8 s with 1 retry · hot DB statement timeout 2 s, batch 60 s · edge request timeout 30 s.

| --- | --- | --- | --- | --- |

Rules:

- **Never cache `unknown`.** The next request must try again.
- No cross-tenant cache entries unless the data is public or hashed.
- Single-flight per key (2 s Valkey lock) prevents stampedes. Stale-while-revalidate is allowed for reputation, **never** for SIM or forwarding status.

## 14. Active-active and disaster recovery

**Model:** every cell is active for its own country. Inside a cell, stateless services run active-active across two zones or data centres. Postgres runs a **single writer** with a **synchronous standby** in the second zone and a witness (Patroni). That gives **RPO 0** and **RTO of 5 minutes or less** for a zone loss. Valkey loss is tolerated, because caches rebuild and rate limits fall back to conservative in-process limits.

| Scenario | Behaviour | Target |
| --- | --- | --- |
| Pod or node loss | Kubernetes reschedules. Guardian calls resume from checkpoint or exit gracefully. | No user-visible impact |
| Zone loss | Automatic Postgres failover to the sync standby | RPO 0, RTO 5 min or less |
| Postgres primary loss | Same as zone loss. Meanwhile the cell enters READ_ONLY. | RTO 5 min or less |
| Whole cell loss | Edge serves a static notice: "Shield is offline. Hang up and call your bank on the number on your card." Bank integrations fall back to `step_up` by contract. | Restore per runbook. Personal data does not fail over abroad. |
| Data corruption | Point-in-time recovery from WAL archive (35 days) into a new cluster | RPO 5 min or less |

**Residency:**

- No personal data crosses cells. Only HMAC-hashed numbers (keys rotate per exchange epoch), aggregates, signed policies and model artefacts do.
- In-country hosting options to confirm: UAE (AWS me-central-1, Azure UAE North or local providers); Kenya (Nairobi colocation such as iXAfrica or Africa Data Centres); Uganda (Kampala colocation such as Raxio); Tanzania (Dar es Salaam colocation such as Raxio or Wingu Africa).
- If edge TLS termination outside the country conflicts with residency rules, sensitive endpoints bypass the edge proxy (DNS-only) or use regional edge services. Counsel confirms per market.

**Releases:** cell by cell. Sandbox → UG 5% → 50% → 100% → TZ → KE → AE, with automatic rollback on error-budget burn.

**Game days:** quarterly zone-failover drill and annual full-cell restore from backup, with measured RPO and RTO recorded in the audit log.

## 15. Realtime

Realtime classes, deadlines, contact-centre streaming, time zones and event delivery are specified in 09. This section covers the console stream, Guardian media and call affinity.

- **Console:** Server-Sent Events at `/v1/stream?topics=cases,holds,mode` with `Last-Event-ID` resume and 15 s heartbeats. Fan-out uses Postgres `LISTEN/NOTIFY` into Valkey pub/sub.
- **Guardian media:** the provider streams the call as μ-law 8 kHz over WebSocket with separate tracks. Shield's own outbound speech track is excluded. The inbound track is the merged call, so scoring uses only the **challenge window**, during which the user has been asked to stay silent. If diarisation finds more than one voice in the window, the voice signal is `unknown`.
- **Call affinity:** each Guardian session is pinned to one media-gateway pod by consistent hashing on the call ID. Challenge state (words, timings, attempts) is checkpointed to Valkey every 2 s. After a pod restart, the session resumes, or the agent says "Shield has to leave this call. Please be careful." and the private result arrives by message.

## 16. AI and model gateway

- Every LLM call (helper chat, console copilot, report summaries) goes through an internal gateway: model allow-list, per-tenant budget, redaction before the prompt, prompt version registry, hashed prompt logs, timeouts and fallbacks.
- **Generative model output is never an input to `decision`, `verdict`, holds or releases.** The engine accepts only typed signals from deterministic sources: detectors, telco APIs, the verified-call registry and reputation.
- Classifier signals (detectors, the story-pressure classifier) are versioned and evaluated. The story signal can **only add risk**. It can never produce Clear.
- What agents say about a result comes from templates filled by the engine and delivered by `send_private_result`. The LLM never words a verdict.

## 17. Security

| Area | Control |
| --- | --- |
| Business authentication | OAuth 2.0 client credentials with `private_key_jwt` and mTLS-bound tokens (RFC 8705), 10-minute tokens. API keys in sandbox only. |
| Console | SSO (OIDC or SAML with the bank's IdP), WebAuthn for operators, step-up authentication for releases and policy activation. RBAC plus region and tenant attributes. |
| Public app | Device-bound keys in Secure Enclave or StrongBox, App Attest and Play Integrity |
| Encryption | TLS 1.3 in transit. AES-256 at rest with per-cell KMS. Envelope encryption. Tenant BYOK (HSM-backed) for evidence. |
| Deletion | Crypto-shred by destroying data keys: per clip for audio, per subject for erasure requests |
| Phone numbers | Stored as HMAC-SHA256 with a cell pepper held in the HSM for lookup, plus an encrypted value only where display is required |
| Secrets | Vault or cloud KMS, 90-day rotation, dual-valid windows for tool and webhook secrets |
| Tenant isolation | Postgres row-level security on `tenant_id`. Dedicated schemas or clusters for top-tier tenants. |
| Supply chain | Signed images (cosign), SBOMs, admission policy that rejects unsigned images |

## 20. Degradation map

| Failure | Effect on signals | Public sees | Bank gets | Mode |
| --- | --- | --- | --- | --- |
| D1 ElevenLabs classifier down | Lose provider-specific positives only | Unchanged | Unchanged | NORMAL, alert |
| One general detector down | Voice can no longer be `no_signs` | More "We can't tell" | More `step_up` | DEGRADED_DETECTION |
| All detectors down | Voice `unknown` | Inconclusive + safe default | Voice `unknown` | DEGRADED_DETECTION |
| Telco API down | SIM and forwarding `unknown` | "We couldn't check the SIM card" | `step_up` for OTP and payee changes | TELCO_DEGRADED |
| ElevenLabs Agents down | Guardian unavailable | "Use Ask-it-yourself: ask the caller something only the real person knows." | Not affected | VOICE_DEGRADED (text-only) |
| WhatsApp API down | Channel down | Results by SMS and push | Not affected | NORMAL, channel incident |
| SMS aggregator down | Failover to secondary | Possible delay | Not affected | NORMAL |
| Postgres primary down | Reads from cache. No new holds or audit writes. | Checks continue. Reports are queued on device. | `SH-MODE-503` with `safeAction: step_up` | READ_ONLY |
| Audit-chain verification fails | State changes stop | Checks continue with an Inconclusive floor | Holds and releases blocked | SAFE_HALT |
| Valkey down | Caches miss and breakers protect the telcos. Conservative rate limits. | Slower | Slower | NORMAL or DEGRADED |
